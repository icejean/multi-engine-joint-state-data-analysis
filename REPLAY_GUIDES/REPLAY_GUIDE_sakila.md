# REPLAY_GUIDE_sakila.md — sakila (anti-memorization / metadata gradient) Replay Guide

> Reproducing the **sakila** metadata-gradient experiment referenced in §4.1 / §7.1③: rename the official MySQL sakila sample DB + add synthetic tables,
> then compare S (single-shot) vs M (agent self-iteration) over three metadata tiers (bare schema / +data dictionary / +ER diagram),
> using the rename/obfuscation to test **anti-memorization** (whether the model cheats by memorizing the public sakila DB).
> Assets: `data/sakila/`, `scripts/`.

---

## 0. Positioning and conventions (read first)

- **Data domain**: relational (SQL). The official MySQL `sakila` sample DB (16 base tables), renamed.
- **Mechanism comparison**: the same 25 questions × three metadata tiers, comparing S (single-shot) and M (agent self-iteration).
- **Anti-memorization**: sakila is a public sample DB; the rename/obfuscation (`rename_map.json`) tests whether the model relies on memorization rather than understanding.
- **Honesty boundary**:
  - **S axis** (single-shot): calls the LLM API directly + scores via pymysql, **fully third-party reproducible**.
  - **M axis** (agent self-iteration): reuses the real DataAI Portal execution chain (openclaw → MCP → dataai-sql kernel), requiring the full Portal stack —
    the open-source DataAI project is at <https://github.com/icejean/dataai_with_jupyterlab_and_rstudio> (`docs/DataAI-Portal-AI数据分析平台简介.md` is the Portal introduction entry).
  - The M axis injects a procedural instruction "check sys_* metadata tables first" (`meta_instr`) into the prompt — an **experimental control** isolating the "does the agent actively use ER" variable, not the Portal's default user message.

## 1. Data source & download

- **Source**: the official MySQL sakila sample DB. Download: <https://dev.mysql.com/doc/index-other.html> → "Example Databases → Sakila Database", direct link `https://downloads.mysql.com/docs/sakila-db.tar.gz` (zip variant `sakila-db.zip`).
- **Import**:

```bash
tar xf sakila-db.tar.gz   # → sakila-db/ (sakila-schema.sql + sakila-data.sql)
mysql -u root -p -e "SOURCE /path/to/sakila-db/sakila-schema.sql"
mysql -u root -p -e "SOURCE /path/to/sakila-db/sakila-data.sql"
```

- **Row-count check** (sakila content is stable; use row counts as a consistency check): `customer 599 / film 1000 / film_actor 5462 / payment 16500 / rental 15420 / store 2`.

## 2. Build three tiers + rename_map (rename/obfuscate + synthetic tables)

```bash
# Idempotently rebuild sakila_rntl / sakila_rntl_m1 / sakila_rntl_meta + export rename_map.json
python3 scripts/build_sakila_rntl.py
```

- Three-tier DBs (same data, metadata increasing tier by tier):
  - `sakila_rntl` (bare schema, no sys tables) → M0 / S0
  - `sakila_rntl_m1` (+ `sys_tables` / `sys_table_fields` data dictionary) → M1 / S1
  - `sakila_rntl_meta` (+ `sys_foreignkeys` ER diagram) → M2 / S2
- 16 base tables renamed (`actr/addr/cust` de-vowel style) + foreign-key columns obfuscated to `ref<N>` + dictionary wording "de-tablename-ized".
- **Synthetic tables** (all idempotently generated by `build_sakila_rntl.py`, no one-off manual steps): `card` (798; payment-card dimension, creating card-swap ambiguity), `awd` (21; composite-foreign-key award table), `doc` (`film_text` renamed + anti-memorization: G/PG/PG-13 subset + 55 titles suffixed "(旧版)").
- Credentials: repo-root `.env` (falling back to `/opt/dataai/templates/.env`).

## 5. Running the benchmark (S / M)

```bash
# S axis (single-shot, third-party reproducible; key read from ~/.openclaw / ~/.claude)
python3 scripts/run_bench_singleshot.py --all --levels S0,S1,S2 \
    --model <model> --base-url <endpoint> --results results_singleshot_<model>.json

# M axis (agent self-iteration, requires full Portal stack; add --backend dsh for domestic-ICT environments)
python3 scripts/run_bench.py --all --levels M0,M1,M2 \
    --model <model> --results results_<model>.json
```

- **Smoke**: `python3 scripts/smoke_test.py` (end-to-end self-check of data source / metadata / gold / scoring).
- **Checkpoint/resume**: results are written per question; already-run `(question_id, level)` are auto-skipped.
