# REPLAY_GUIDE_tabred.md — TabReD weather (ML direction, Python + R) Replay Guide

> Reproducing the §5.2 / §5.3 **TabReD weather** machine-learning experiment from scratch:
> data acquisition → Python LightGBM full pipeline → R (rtorch MLP + float32 direct-channel GBDT) → result comparison.
> This is the cross-dataset reproduction of the "LLM × ML multiplication" (default parameters, not a tuning-SOTA sprint), unlike the SQL/Cypher "questions/gold/scoring" framework.
> Assets: `data/tabred/`, `scripts/`.

---

## 0. Positioning and conventions (read first)

- **Data domain**: ML (tabular regression). TabReD's `weather` dataset (16,951,828 rows × 104 columns, target `fact_temperature`).
- **Mechanism significance**: an LLM cannot fit a ten-million-row GBDT on its own; this experiment proves the "persistent kernel (Python/R) executes the LLM's semantic instructions with precise computation" multiplication — reproduced cross-dataset (TabReD) and aligned cross-engine (Python/R).
- **Honesty boundary**: this experiment uses **default parameters**, **not** a tuning-SOTA sprint (trailing the tuned SOTA by +5.6%); tuning is a senior expert's high-skill job, a different dimension (paper §5.2 honesty boundary).
- **Runtime environment**: full 16.95M peaks at ~7GB (Python) / ~10.5GB (R GBDT); run on a 24G laptop (a 7.5G machine can't).

---

## 1. Data source & download

- **Source**: TabReD (A Benchmark of Tabular Machine Learning in-the-Wild), `weather` dataset.
  - Repo: <https://github.com/yandex-research/tabred>
  - Download: `uvx tabred download` (requires a Kaggle account), giving `weather.parquet`.
- **Included in this repo**: `data/tabred/chat-*.html` (5 desensitized conversation logs, showing the conversation-driven full pipeline).
- **Not included**: `weather.parquet` (raw data, large), `weather_10pct.parquet` (10% sample, generated by a script).

---

## 2. Python full pipeline (LightGBM, full scale)

```bash
# Full 16.95M: float32 + time split (train<2023-07-01 / test>=) + LightGBM default params
/usr/lib64/anaconda3/envs/graphrag/bin/python scripts/spike_tabred_weather_full.py
#   data source data/tabred/weather.parquet; target fact_temperature
#   result: test RMSE 1.5450 / R² 0.8408 (fit 346s)
```

- Related scripts: `spike_tabred_weather_full_mem12.py` (12G-memory variant), `spike_tabred_weather.py` (10% sample smoke), `spike_tabred_weather_torch_fixed_10pct.py` (Python torch 10% counterpart).

---

## 3. R GPU deep learning (rtorch MLP, 10% sample)

```bash
# 10% sample (1.7M) + MLP (3×256) + AdamW + MSE, default time split; data resident in GPU memory throughout
Rscript scripts/spike_tabred_weather_torch_10pct.R
#   result: test RMSE 1.5419°C (5 epochs, 3.3 min); Python GPU counterpart 1.5387
```

- 10% sample: `weather_sample_10pct.py` writes `weather_10pct.parquet` once (the script auto-invokes it if missing).
- Aligned item-by-item with the Python version: N_EPOCHS=5, BATCH_SIZE=1024, N_BLOCKS=3, D_BLOCK=256, SEED=0, meta columns lat/lon/station_id excluded.

---

## 4. R float32 direct-channel GBDT (full scale)

```bash
# Full 16.95M: float32 direct channel (C++ gbdt_float.cpp), peak memory ≤10GB
/usr/bin/time -v Rscript scripts/run_gbdt_float_full.R   # VmHWM records peak RSS
#   result: test RMSE 1.5449 (peak 10.56 GiB)
```

- Dependencies: `scripts/gbdt_float.cpp` (Rcpp sourceCpp compile) + `scripts/spike_lgb_float32.cpp` (float32 LightGBM smoke).

## 5. Result comparison

| Engine | Approach | Data | Result |
|---|---|---|---|
| Python | LightGBM default params (full) | 16.95M | RMSE 1.5450 / R² 0.8408 |
| Python (counterpart) | torch MLP (10%) | 1.7M | RMSE 1.5387 |
| R | rtorch MLP (10%) | 1.7M | RMSE 1.5419°C |
| R | float32 direct-channel GBDT (full) | 16.95M | RMSE 1.5449 (peak 10.56 GiB) |

> Official convention: TabReD weather full-scale test RMSE 1.5450 / R² 0.8408 (default params); 10% sample ≈ full scale (diff 0.0011, 10% saturated). Exact numbers are authoritative in `analysis/tabred-weather-ml-benchmark-spec.md` and the chat records.
