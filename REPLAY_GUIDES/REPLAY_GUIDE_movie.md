# REPLAY_GUIDE_movie.md — movie (CypherBench graph) Replay Guide

> Reproducing the §5.1 **movie** (CypherBench movie subgraph, Neo4j) graph-query experiment from scratch:
> data acquisition → Neo4j import → schema/gold → running M+S → scoring → convergence trajectory & root cause.
> Assets: `data/movie/`, `scripts/`, `analysis/root-cause/`.

---

## 0. Positioning and conventions (read first)

- **Data domain**: graph (Cypher → Neo4j). CypherBench's movie subgraph (401 questions; 459,393 nodes / 1,892,202 relationships / 7 labels / 9 relationship types).
- **Mechanism**: **M+S** (one-shot injection of `movie_schema.json` + `movie_notes.md`; the agent produces raw Cypher through multi-round execution feedback); no S/M metadata tiers (single graph, single mode).
- **Honesty boundary**: M+S goes through the real Portal execution chain, requiring the full DataAI Portal stack —
  the open-source DataAI project is at <https://github.com/icejean/dataai_with_jupyterlab_and_rstudio> (`docs/DataAI-Portal-AI数据分析平台简介.md` is the Portal introduction entry).
- **Scoring**: `score_cypher.py`'s `results_equal_relaxed` (value multiset comparison, relaxed on extra columns, NULL/empty-string equivalent, numeric tolerance 2 decimals).

- **Source**: CypherBench, movie subgraph.
  - Repo: <https://github.com/megagonlabs/cypherbench>

- **Not included**: `*_simplekg.json` (raw JSON, large), `import/*.csv` (node/relationship CSVs, 83MB, generated by import_movie.py).

## 2. Preprocessing (export CSVs)

```bash
# Stream *_simplekg.json into neo4j-admin import CSVs (no full in-memory read)
python3 scripts/import_movie.py movie data/movie/import
#   → data/movie/import/{nodes_<Label>.csv, rels_<Type>.csv, run_import.sh}
```

- Node IDs use Wikidata `eid` directly (e.g. `Movie#Q1000094`), globally unique; relationship CSV subj/obj map directly to `:START_ID/:END_ID`.

---

## 3. Database creation & loading (Neo4j)

```bash
cd data/movie/import
bash run_import.sh      # neo4j-admin database import full (nodes + relationships)
```

- Requires Neo4j 4.4+ (movie graph). `run_import.sh` is auto-generated by `import_movie.py`.

## 4. Question set (401 questions)

- **Single source of truth**: `data/movie/test_movie.json` (401 questions, with `question` / `gold_cypher` / `answer_json` / `match_category`).

## 5. schema / gold source / generation / fixes

```bash
# schema resource file (node labels/properties + relationship types/directions → movie_schema.json)
python3 scripts/gen_schema_movie.py

# gold: execute each test_movie.json gold_cypher → gold.json
python3 scripts/gen_gold_movie.py
```

- **gold fixes** (see `analysis/gold-verification.md`): before evaluation, fixed 6 non-deterministic gold entries (`ORDER BY sparse attribute DESC LIMIT 1` null ordering) + 4 comparison-question duplicate-name cartesian products, making gold 401/401 deterministic.
- Difference from SQL: the graph has no "empty-set aggregation → NULL" degeneration, nor SQL-dialect execution failures — all 401 gold_cypher are executable and deterministic.

## 6. Resource files (M+S one-shot injection)

- `data/movie/movie_schema.json` (authoritative graph structure) + `data/movie/movie_notes.md` (Cypher conventions, see §10 convergence).

## 7. Running the benchmark

```bash
# M+S (inject schema + notes; final answer is raw Cypher, audit logged to ~/log/<chat_id>.cypher)
python3 scripts/run_bench_movie.py --all --results results_movie_mplus.json

# pass^3 (all-3 / union)
python3 scripts/run_bench_movie.py --all --results results_movie_mplus_r2.json   # round 2/3
# summarize three rounds → pass3_summary.md

# convergence summary (read one round's results → convergence.json)
python3 scripts/summarize_convergence.py --db movie --results results_movie_mplus.json \
    --round 1 --notes "v1(initial schema + basic notes)"
```

- **Checkpoint/resume**: results are written per question; already-run questions are auto-skipped.
- **Exploration variants** (result-file prefix = process): `mplus` (round1 initial) → `mplus_r2/r3`, `r4/r4b` (convergence rounds) → `final`/`final2` (v4 final); `pass2/pass3` (pass^3 three rounds); `q2q52` (subset validation). The convergence trajectory 85.8%→95.0%→96.5% is in `convergence.json`.

## 10. Iteration timeline (convergence process, not per-round numbers)

1. **Import + schema/gold**: `import_movie.py` exports CSVs → `run_import.sh` builds the Neo4j graph → `gen_schema_movie.py` / `gen_gold_movie.py`.
2. **round1 (v1)**: initial schema + basic notes, getting the lower bound.
3. **root cause → fix notes → re-run**: root-cause the failures (duplicate-name node dedup / NULL ordering / inconsistent Genre.name values), distilling them into notes rules one by one and re-running — converging to 96.5% EX.
4. **pass^3**: all-3 / union, quantifying model drift.
5. **Closure**: lock the 6 hard-floor questions (duplicate-name node data defects) + 18 model-drift questions.

> Exact numbers are authoritative in `convergence.json`, `data/movie/pass3_summary.md`, and the corresponding `results_movie_*.json`.
