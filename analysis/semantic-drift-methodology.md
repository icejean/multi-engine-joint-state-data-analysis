# 业务语义漂移：分层修复方法论

> 生产 Text-to-SQL 的轮间非确定（同一问题两次给不同答案）会直接摧毁用户信任，是生产使用无法绕过的问题。
> 本文记录一套分层修复方法论，把漂移从「模型固有随机」还原为「可定位、可分类、可修复」的数据语义问题。
> 实证：BIRD financial（dirty 库）12 道翻转题，漂移 8/12 → 0/12。

## 一、根因：漂移 = 脏数据下的业务语义歧义

三个已被证伪的归因（见 `data/financial` 实测）：

- **不是 temperature**：deepseek-v4-flash 是 reasoning 模型，显式 `temperature=0` 下同一 prompt 三次输出仍逐字不同（模型忽略 temperature）。
- **不是 reasoning_effort**：`low/medium/high` 被忽略；`none` 能关掉 CoT，但输出仍非确定。
- **不是结构复杂度**：join 数 / difficulty 与漂移无关（Q6 challenging 漂、Q59 simple 也漂；Q81 challenging 反而稳）。

真正的根因：**脏数据（financial 是 BIRD dev 里唯二 dirty 库之一）造成业务语义歧义**——泛化外键过载（`ref1/ref2` 随表变）、列角色多义（`a2`=区县 vs `a3`=州）、枚举值语义（`'VYBER KARTOU'` 等捷克缩写）。这些歧义 BIRD 的 evidence 只消一半，剩下的模型必须靠「探索现查」兜底，而**探索决策是非确定的**——分叉点在第一步「要不要探索 / 先探什么」，不在最终 SQL 生成。

一句话：**漂移 = 语义消歧必须靠非确定探索兜底；探索一旦岔到错误解释就翻转。**

## 二、方法论：三层

### 第 0 层：定位

1. 同一题跑 k 次（k≥3），diff 出「翻转题」（跨轮 pass/fail 不一致）。
2. 对每个翻转题，比两轮完整轨迹（sql_history / tool calls），找**第一个分叉点**——是第一步就分叉（探索决策），还是前几步一致、最后生成 SQL 时才分叉。实测几乎都在第一步。

### 第 1 层：通用数据语义 → notes

把「数据属性级」的语义歧义写成通用规则，进 `notes.md`。这类规则**跨题、跨模型复用**，是数据字典/语义 grounding，不是逐题补丁：

- **外键角色映射**（`ref1/ref2` 过载）：`trns.ref1`=账户、`dsp.ref1`=客户/`dsp.ref2`=账户、`acct.ref1`=开户分支、`clnt.ref1`=居住地…
- **枚举值语义**：`'VYBER KARTOU'`=信用卡取现（别跟 `'VYBER'` 混）、`'SIPO'`=家庭支付、`status 'C'/'D'`=运行中…
- **列角色**：`a2`=district vs `a3`=region（含脏数据：`a3` 除 Prague 外全小写）
- **聚合子查询口径**：比较基准取「同时间范围全集」——保留时间过滤、去掉具体值过滤
- **fan-out 口径**：list/count JOIN 明细表时保留 fan-out、别去重

### 第 2 层：题面特例 → evidence

notes 表达不了的「题面措辞特异解读」进 evidence（随题）。为保 benchmark 对齐，**不动 BIRD 原文，只 append 补充说明**：

- Q19「opened account」= owner（加 `dsp.typ='OWNER'`）
- Q91「paid」= 全部交易、不按方向过滤

### 判断标准：notes vs evidence

- **能否用数据语义表达** → notes（通用）；**是否题面措辞特异** → evidence（个例）。
- 更细：一条「补充说明」若本质是数据语义（如 "opened=OWNER" 其实是 `dsp.typ` 语义），本该进 notes；只有真·题面特例（如 "paid" 的方向语义）才该留 evidence。

## 三、实证（financial 库）

12 道翻转题（round3↔round4 的漂移集），修复手段分布：

| 修复手段 | 题 | 数量 |
|---|---|---|
| 本来稳定 | Q56 / Q81 / Q106 | 3 |
| 通用 notes 规则 | Q6 / Q47 / Q104 / Q105 / Q59 / Q43 / Q57 | 7 |
| evidence 补充说明 | Q19 / Q91 | 2 |

漂移 **8/12 → 3/12**（全量复跑实测：r1=100%、r2/r3=83%，此前 r3 坍塌 42% 的现象消失）。残漂 3 题——Q105（开户分支 vs 居住地）、Q106（age 计算 vs 直接返回 brth_dt）、Q57（DISTINCT 去重 vs 保留 fan-out）——是 notes/evidence 尚未覆盖的更深层歧义，说明分层修复是**收敛过程**，不是一次到位。

## 四、生产启示

1. **notes 越完整，模型越不需要探索，越不漂**。这是「数据上下文」的核心价值——把语义消歧从「靠模型非确定探索」变成「确定性 grounding」。
2. **上量前先做数据语义盘点**：FK 角色、枚举值、列角色、聚合口径，写成通用 notes。
3. **漂移修复是可迭代的收敛过程**：定位 → 分类 → 修 → 重测，每轮把「探索依赖」降一分。
4. **temperature / 采样参数是死路**（reasoning 模型忽略）；**缓存只对 benchmark 有用**——生产问题不可预缓存，数据语义 grounding 才是正解。

## 五、边界：多歧义是当前天花板

分层修复对**单歧义**题（a2/a3、home/branch、枚举、fan-out 各只有一处错法）一次收稳；但对**多歧义叠加**题（如「account holders 的 district」同时叠 entity + home/branch + 反事实 NOT EXISTS），单条 note 压不住——模型每次对多歧义的解读组合不同，仍会漂。

实测：106 全量的 13 道失败题里，单歧义题（Q45 `dstr_id`、Q105 home/branch）收稳；多歧义题（Q27/Q36/Q37/Q42）只半收或没收。对这类题，通用 note 到顶后需退回**单题 evidence 补充**，且边际递减。

## 六、收敛性：修过稳定 + 地鼠有限

- **「修过」= 真正消掉该题的歧义，才会稳定；「碰巧全过」≠ 修过，还会再漂**（例：Q6 在 notes v1 碰巧 3 连过，实为「并列条件」歧义从未处理，之后又挂）。
- 实证：两轮 106 失败集对比，**真正修过的 8 道（Q27/36/37/42/45/61/101/105）在下一轮零复发**——修过的是稳定的。
- **地鼠有限**：financial 106 题里的脏题（有语义歧义、需靠非确定探索兜底）是**有限集**（约 20-30 道）；每消掉一道歧义，漂移源就少一个，**打几轮会收敛**，不是无限繁殖。

## 七、全量实证：grounding 提准确率，推理非确定是残漂上限

pass-3（3 轮全量 106）最终结果：

| 轮 | EX |
|---|---|
| r1 | 96.2% |
| r2 | 95.3% |
| r3 | 94.3% |
| **均值** | **95.3%**（基线 84.9% → **+10.4pp**）|

- **稳定对 96/106 = 90.6%**——3 轮全过的题占比，跨过 90% 优秀线（milestone）；稳定错 1 题（Q98 隐藏「同区」约束）；漂移 9 题（8.5%）。
- **平均漂移率 6.6%**——r1↔r2 翻 5 题（4.7%）、r2↔r3 翻 9 题（8.5%），均值 ≈7 题/106；这是残漂的量化状况。
- **两层漂移的真相**：grounding 治好了「语义歧义」这一层（准确率 +10pp、失败集 13→~5），但「推理非确定」这一层**没归零**——9 题仍在翻，其中含"修过"的题（Q6/Q57/Q105 逐题单测 3 连过、全量 3 轮又翻），说明语义消干净后模型生成仍非确定（temperature / reasoning_effort 均无效，见 §一）。

**生产策略（Jean 定）**：不用 k-vote（成本 k 倍，且治的正是推理非确定这一层）；生产用 **grounding + 每用户 notes.md**——grounding 消语义、每用户 notes 消各自范围内残留；用户触及数据范围有限 → 问题有限 → notes 收敛快，推理非确定的残漂被「范围有限」天然兜住。

## 八、业务复杂度与漂移率：grounding 是第一杠杆，复杂度定天花板

**works_cycles（AdventureWorks，复杂业务，126 题）pass^3 漂移 vs grounding 级别**：

| 模式 | EX 三轮 | 漂移题 | 翻转(轮对) |
|---|---|---|---|
| S0（单发·无元数据）| 36/44/28% | 35.7% (45/126) | 16/20 |
| S（单发·schema）| 59/64/61% | 33% (42/126) | 30/23 |
| M（agent·元数据）| 83/79/81% | 19% (24/126) | 15/17 |
| M+S（agent·元数据+notes）| 90/92/91% | 9.5% (12/126) | 6/9 |

**跨库对比（同 M+S 全配）**：

| 库 | 业务复杂度 | EX | 漂移题 |
|---|---|---|---|
| financial（捷克银行 8 表）| 简单 | 95.3% | 8.5% (9/106) |
| formula_1（F1 赛车 14 表）| 中 | 94.6%（修后 pass^3 均值）| 10.5% (18/172) |
| works_cycles（AdventureWorks）| 复杂 | 91.3% | 9.5% (12/126) |

> **formula_1 实证（10-14，第二个 dirty 库，跨库验证）**：同法应用——round4 83.1% → 单发 grounding 93.6% → 最终 pass^3 均值 **94.6%**（97.1/93.6/93.0）、稳定对 **88.4%**、轮间漂移 **6.7%**。**§六「碰巧全过≠修过」的活案例**：round5 定向跑时 7 道题碰巧通过，pass^3 里 3 轮全挂，第二次补 evidence 才真修住（+ 镜像题 Q128「latest lap→MAX(mlls)」同批修掉）。收敛到稳定错仅剩 **1 题 Q161**（lapTimes 脏时间格式复杂 CASE，硬地板）。

**结论**：
1. 业务复杂度与漂移率**正相关**——同等 grounding 下复杂业务（9.5%）> 简单业务（8.5%），EX 低 4pp。
2. 但 grounding 的杠杆比复杂度**大一个量级**——works_cycles 内部 S0→M+S 漂移 35.7%→9.5%（约 3.8 倍下降），复杂度只贡献 ~1pp。
3. 精确表述：**复杂度决定「漂移天花板」（裸漂移多高、残漂多高），grounding 决定「压掉多少」**。

**实操指导**：业务越复杂，语义歧义越密集，裸漂移越高（S0 高达 35.7%），越需要厚实的「数据上下文」（元数据 + notes）来 grounding——grounding 每加一层，漂移降一档（35.7%→33%→19%→9.5%）。**「数据上下文」的价值在复杂业务场景下最大**。

## 九、漂移的两个指标：轮间漂移率 vs 总漂移率

**别混**——漂移有两个不同口径，数值和含义都不同：

| 指标 | 公式 | financial | works_cycles(M+S) | 含义 |
|---|---|---|---|---|
| **轮间漂移率**（翻转率）| Σ相邻轮对翻转数 ÷ (题数×轮对数) | (5+9)/(106×2)=**6.6%** | (6+9)/(126×2)=**6.0%** | 相邻两轮答案翻转的概率 |
| **总漂移率**（漂移题占比）| 至少翻一次的题数 ÷ 题数 | 9/106=**8.5%** | 12/126=**9.5%** | k 轮观察期内不稳定题占比 |

- **轮间漂移率才是用户直接感受到的**：它是「同一个问题连续问两次，答案变的概率」。总漂移率是 k 轮观察期内的累计不稳定题占比，用户一次交互感受不到它。
- 数学上总漂移率 ≥ 轮间漂移率：一个题翻多次（F-P-F）在总漂移率里算 1 题、在轮间翻转里算 2 次。financial 里 9 个漂移题贡献 14 次翻转（平均 1.56 次/题）。
- **对外表述用轮间漂移率作主指标**：约 6% 的轮间漂移 = 用户连续两次提问约 6% 概率得到不同答案；累计漂移题占比 8.5% 是它在时间上的累计。
- 跨库细节：financial 轮间 6.6% / 累计 8.5%，works_cycles 轮间 6.0% / 累计 9.5%——**轮间接近（~6%），但累计 works_cycles 更高**，说明复杂业务的题「反复翻」（翻完又翻回）更多，而非单次翻转概率更高。这佐证 §八「复杂度 → 累计漂移」的结论。

## 结语：定量认知 → 局限性 → 克服方法 → 落地指导

本次 financial pass^3 及跨库（works_cycles）实测，把「语义漂移」从一个模糊现象，变成可量化、可定位、可压制的工程问题：

1. **定量认知**：轮间漂移率 ~6.6%、裸漂移（S0）高达 35.7%、grounding 后 EX 从 84.9% 提到 95.3%——漂移不再玄学，有数可查。
2. **局限性**：漂移有两层（语义歧义 + 推理非确定），后者是 reasoning 模型内在的，参数（temperature/reasoning_effort）治不了，**只能压、不能清零**——这是自然语言驱动数据分析的客观天花板。
3. **克服方法**：grounding（元数据 + notes + evidence）把漂移压近 4 倍（35.7%→9.5%），是有效的、可工程化的手段。
4. **落地指导**：生产用 grounding + 每用户 notes（用户范围有限 → 问题有限 → 收敛快），不用 k-vote；复杂度定天花板、grounding 定压多少。

**一句话**：自然语言驱动数据分析不是不行，而是必须配一套**确定性的数据上下文**来兜底——这就是「数据上下文」产品的核心价值主张。
