## A 级（必补）

### A1. 统一 gold 口径重判三机制（works_cycles 126）

- **问题**：头条 97.6% 是 **pass4 gold**（修 35 处 + 额外 3 处）；S 87.3% / M 92.1% 是 **round5 gold**——口径不一，审稿人第一刀就砍这里。
- **做什么**：用 pass4 最终 gold，把 S（S1/S2 最优档）和 M（M0 最优档）的既有结果**重判**。
- **能否复用**：✅ **大概率能，不重跑 LLM**——判分是「结果集等价」（`results_equal_relaxed`），只要 `results_wc_*.json` 里存的是每题的 SQL/结果集而非「对错」标记，用新 gold 重判即可。**先查 results json 存了什么**。
- **产出**：同口径的 S / M / M+S 对比表（第 4 节的 Table 1 地基）。

### A2. 三库 × 机制 × 模型的干净矩阵

- **问题**：各库各机制散在不同口径、不同轮数。
- **做什么**：一张矩阵，行 = {works_cycles, financial, formula_1}，列 = {S, M, M+S}，每格填 pass@1 + pass^3 + 漂移率。
- **能否复用**：M+S 三库已有；S/M 需按 A1 补同口径值。
- **产出**：论文第 4 节主表。

### A3. 配对显著性检验（McNemar）

- **问题**：只有点估计，没有显著性。Cube（arXiv:2604.25149）用 McNemar p≤0.0015，审稿人会期待同级别检验。
- **做什么**：M+S vs S、M+S vs M，在 126 题上用**逐题对错**做配对 McNemar。
- **能否复用**：✅ 能——pass^3 三轮逐题记录即可，**零 LLM 成本**。
- **产出**：p 值，证明机制差在显著性之外。

## B 级（应补）

### B1. single-shot 在 dirty 库的同库基线（financial / formula_1）

- **问题**：「领先 Single-Shot SOTA 15-20pp」现在是**跨系统对比**（借 MCI-SQL 76.41% 当 single-shot 参照），带 systems 差异 caveat。
- **做什么**：在两个 dirty 库跑 single-shot（S1 字典满配口径），得到**同库** S vs M+S 对照。
- **能否复用**：❌ 要重跑 LLM（两库各一轮 single-shot，成本低）。
- **价值**：把「领先 SOTA」从跨系统升级为**同库对照**，caveat 大减——这是 B 级里性价比最高的一项。

### B2. glm-5.2 的 M+S pass^3（works_cycles）

- **问题**：跨模型只有单跑（glm-5.2 92.1%/94.4% 单跑），没有跨模型的方差/漂移对照。
- **做什么**：glm-5.2 跑 works_cycles M+S pass^3（三轮）。
- **能否复用**：❌ 要重跑 LLM（3 轮 × 126 题）。
- **产出**：deepseek（漂移 10%）vs glm 的方差/漂移对照，坐实「弱模型方差大」。

### B3. bootstrap 95% CI

- **问题**：所有准确率都是点估计。
- **做什么**：对每个准确率点，bootstrap 重采样给 95% CI。
- **能否复用**：✅ 能——从 pass^3 三轮数据重采样，**零 LLM 成本**。
- **产出**：误差棒，让「+18.9pp」这类数字有置信区间。

## 建议执行顺序（按「零成本优先 → 花钱的留后」）

1. **先做零成本的**（A3 McNemar、B3 CI、C1 pass@k）——纯复用 pass^3 数据，1 天内可出，先立住「显著性 + 置信区间」。
2. **A1 重判**——先查 `results_wc_*.json` 存的是结果集还是对错；存结果集则零成本重判，存对错则要重跑。
3. **B1 同库 single-shot 基线**——性价比最高，把「领先 SOTA」从跨系统升级为同库对照，建议优先于 B2。
4. **B2 glm-5.2 pass^3**——坐实跨模型方差。
5. C 级按剩余时间插空。

> 前提检查（执行前先确认）：`dataai-test/scripts/` 下是否已有跑 pass^3 的脚本可复用（`run_bench_wc_mplus.py` 之类）；`results_wc_*.json` 的字段结构（是否存结果集/SQL，决定 A1 是否零成本）。
