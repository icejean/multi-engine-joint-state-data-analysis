# M 轴全量根因分析（126 题 × M0/M1/M2，evidence+prompt+gold 全修后 v2 终版）

> 数据源：`results_wc_m_126_full_v2.json`（终版）。当前 M0=75.4 / M1=71.4 / M2=76.2。
> 本文回答：① M 轴剩余 43 道失败是什么；② agent 相对 single-shot 的优势/劣势在哪；③ 还有哪些可改善。

---

## 0. 失败总览

- 唯一失败题 **43 道**；三档全挂 **21**、两档 **12**、单档 **10**。
- 失败实例 97 次：**答错（有 SQL 不等价）92 次**、超时 4 次、SQL 执行错误 1 次。
- **关键**：M 轴的失败 ~90% 是「答错」（与 S 轴共享的 gold/evidence/拆列/语义硬地板），M 轴专属的「迷路/超时」只剩 **10 次**（4 超时 + 6 探索语句当终答），比 v1 的 ~15 次已下降——**收敛提示词起效了**。

---

## 1. 两轴对照：agent 的机制优势是「真实但有限」

按「三档全挂」对比（S 轴 22 道 vs M 轴 21 道）：

| 类别 | 题数 | 题目 |
|---|---|---|
| **两轴都三档全挂（硬地板）** | 14 | 10/14/15/30/37/38/50/54/79/90/110/112/117/118 |
| **M 独挂三档（agent 反而差）** | 7 | 7/29/61/70/81/99/114 |
| **S 独挂三档（agent 救回）** | 8 | 12/13/33/45/57/71/72/119 |

**结论：agent 的探索机制「救 8 题、害 7 题」，在硬地板层面几乎打平。** 真正的 agent 优势在**端点**（M0>S0 +11pp、M2>S2 +3pp），不在「中间档的逐题胜负」。

### M 独挂的 7 题（agent 为什么反而差）
- 都是「探索救不了」的语义/口径类：Q7（>1 语义）、Q29（最新值）、Q70（full name 三列）、Q81（evening 口径）、Q114（month 格式）、Q99（BOM 递归 DISTINCT）、Q61（**唯一真·迷路超时**）。
- 只有 Q61 是 agent 专属的「探索迷路」，其余 6 题和 S 轴同源。

### S 独挂的 8 题（agent 为什么救得回来）
- 都是「靠试错能找对」的题：Q12（GROUP BY）、Q13（去重）、Q45（折扣反号）、Q119（tiebreaker）、Q33/Q57/Q71/Q72（join/最新值）。
- 这正是 agent 的价值——single-shot 猜不中、agent 跑一下就能发现。

## 2. 剩余失败的五类根因（与 S 轴共享 ~90%）

| 根因 | 代表题 | 可修 |
|---|---|---|
| **① gold 口径怪癖** | Q37(加权均值)、Q38(on sale=offer vs 卖期)、Q110(customer=person only)、Q119(tiebreaker)、Q30(时段 vs 名字) | ✅ gold 核定 round3 |
| **② evidence/题面残留** | Q54(年份漂移)、Q81(Evening)、Q10(private 正反)、Q15(比值 vs 百分比) | ✅ evidence 核定 round3 |
| **③ 拆列/CONCAT/fan-out** | Q112/Q117/Q118(名字+spurious emp join)、Q70(三列)、Q50/Q52(DISTINCT) | ✅ gold 归一 |
| **④ M 专属：迷路/超时** | 4 超时 + 6 探索语句 | ✅ 加超时 + 加强收敛 |
| **⑤ 固有语义歧义** | Q14(accounts)、Q90(双重歧义)、Q79(LIKE 匹配) | ❌ 硬骨头 |

## 3. 改善清单（按 ROI）

1. **[gold 核定 round3]（~5 题，静态改 gold）**：Q37/Q38/Q110/Q119/Q30——agent 的答案语义更对、gold 口径有问题，改 gold 重判即翻。
2. **[evidence 核定 round3]（~4 题，静态改 evidence）**：Q54(年份漂移)、Q81(Evening)、Q10(private 正反)、Q15(比值*100)。
3. **[拆列/CONCAT 归一]（~6 题）**：Q112/Q117/Q118/Q70/Q50/Q52——统一「full name」表示 + 判分对 fan-out 放宽。
4. **[M 专属：加超时 + 强收敛]（~10 次）**：`AGENT_TIMEOUT` 240→360 救 4 超时；meta_instr 收敛句再收紧（「最多 N 轮、拿不准就交最优解」）压掉 6 迷路。
5. **[固有语义歧义]（~4 题）**：Q14/Q90/Q79/Q7——BIRD 原题含糊，不修或逐题拍板。

> 做完 1+2+3（纯静态、不调 LLM）预期 M 轴再 +5~8pp，且对 S 轴同样生效（gold/evidence 两轴共享）。

---

## 4. 诚实边界（写进报告）

1. **单次跑方差仍是主噪声**：M 轴单次 ~±5-8pp。M1(71.4) < M0(75.4) 的 4pp 是方差（v1 里 M1>M0、v2 里 M1<M0，方向相反），不能当「字典有害」的结论。
2. **能信的只有端点**：M0>S0（+11.1）、M2>S2（+3.2）是稳的；中间档排序（S1 vs M1、M1 vs M0）不可信，需 pass@k 才能定。
3. **agent 的机制价值不在「单条 SQL 更准」**，而在：裸库探索红利（M0>S0）+ 大 schema 不预注入（S2 反而被 ER 拖累，M2 按需查不受累）——这是 M 轴真正的叙事，与「单条 SQL 是平价商品」不冲突。
